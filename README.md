# T&M Sound — система бронирования

Отдельное production-ready приложение (Next.js + PostgreSQL + Telegram-бот),
которое даёт клиентам сайта реально бронировать студию: выбор услуги, даты,
свободных часов, продолжительности — и заявку с подтверждением через
Telegram. Существующий дизайн-канвас сайта не тронут — эта система
подключается к нему только ссылкой на кнопке «Записаться».

Почему это отдельный проект, а не часть канваса, и как их объединить в
будущем — см. [ARCHITECTURE.md](./ARCHITECTURE.md).

## Что внутри

- `prisma/schema.prisma` — 4 таблицы: `services`, `bookings`,
  `blocked_slots`, `settings`.
- `prisma/migrations/20240101000100_overlap_protection/` — защита от
  двойного бронирования НА УРОВНЕ БАЗЫ ДАННЫХ (PostgreSQL `EXCLUDE`-
  ограничение). Это проверено вручную реальными SQL-запросами при
  разработке: пересекающиеся активные брони база отклоняет сама, даже
  если два запроса пришли одновременно — раньше, чем успел бы
  выполниться любой код на JS.
- `src/app/api/**` — backend: услуги, доступность по датам/часам,
  создание брони, вебхук Telegram-бота.
- `src/app/booking/**`, `src/components/booking/**` — сам booking-flow
  (7 шагов, мобильный, в стиле сайта).
- `src/lib/**` — бизнес-логика: расчёт свободных часов, цены, тексты
  уведомлений, админ-команды бота.

## Локальный запуск

Здесь, в песочнице, где собирался код, нет доступа к npm-реестру — сам
установить зависимости и прогнать `npm run build` я не смог. Поэтому
**первым делом у себя** прогоните сборку, чтобы поймать опечатки раньше
деплоя:

```bash
npm install
npm run build
```

Дальше — с реальной базой:

```bash
cp .env.example .env
# впишите DATABASE_URL (см. ниже, «База данных»)
npx prisma migrate deploy   # накатит обе миграции, включая overlap protection
npm run db:seed             # 5 услуг с сайта + рабочие часы Пн–Вс 10:00–23:00
npm run dev                 # http://localhost:3000/booking
```

Booking-флоу уже откроется и будет работать (создание заявок, календарь,
свободные часы). Telegram-уведомления заработают после следующего шага.

## Telegram-бот

1. Откройте **@BotFather** в Telegram → `/newbot` → придумайте имя и
   username (должен заканчиваться на `bot`, например
   `tmsound_booking_bot`).
2. BotFather даст **токен** — вставьте в `TELEGRAM_BOT_TOKEN`, а username
   (без `@`) — в `TELEGRAM_BOT_USERNAME`.
3. **Chat ID администратора** (это ваш личный чат с ботом, куда будут
   падать заявки): напишите новому боту что угодно (`/start`), затем
   откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — в ответе будет
   `"chat":{"id": 123456789, ...}`. Это число — `TELEGRAM_ADMIN_CHAT_ID`.
4. Придумайте случайный `TELEGRAM_WEBHOOK_SECRET` (например
   `openssl rand -hex 20` в терминале) — он защищает вебхук от чужих
   запросов.
5. После деплоя (см. ниже) впишите `PUBLIC_APP_URL` (адрес, который выдал
   хостинг) и выполните:
   ```bash
   npm run bot:set-webhook
   ```
   Это одна команда — она говорит Telegram, куда слать сообщения.

Дальше бот работает сам: заявки с сайта приходят вам с кнопками
✅ Подтвердить / ❌ Отклонить / 💬 Написать клиенту, а клиенту после того
как он нажмёт «Открыть бота → Старт» на странице подтверждения заявки —
статус записи.

Управление — через `/menu` (или просто `/start`): всплывает клавиатура
с кнопками — Сегодня, Завтра, Неделя, Все записи, Свободные часы,
подсказка по блокировке. Под каждой подтверждённой бронью в списках —
своя кнопка **❌ Отменить**, жать не выходя из списка. Те же действия
доступны и текстом, если привычнее: `/today`, `/tomorrow`, `/week`,
`/bookings`, `/free [дата]`, `/block 28.08 15:00-18:00 Причина`.

(Полноценного переноса брони на другое время пока нет — если нужно
перенести, отмените кнопкой и попросите клиента записаться на сайте
заново на новое время. Скажите, если нужен отдельный поток для переноса
одним действием — это отдельная небольшая доработка.)

Чтобы команды всплывали автодополнением при вводе `/` в чате с ботом
(не печатать руками) — один раз выполните:
```bash
npm run bot:set-commands
```

## База данных

Нужен PostgreSQL 14+ (используется расширение `btree_gist` и
`EXCLUDE`-ограничения — это стандартная часть PostgreSQL, доступна на
любом провайдере). Варианты, если своего сервера нет:

- **Neon** (neon.tech) — бесплатный план, отдельная БД без привязки к
  хостингу приложения.
- **Supabase** (supabase.com) — тоже бесплатный план, чуть больше
  возможностей сверху (не обязательны).
- **Railway Postgres** — если хостите само приложение на Railway, там
  же одной кнопкой добавляется Postgres-плагин в тот же проект, и
  `DATABASE_URL` подставляется автоматически.

В любом случае — скопируйте строку подключения в `DATABASE_URL` и
прогоните `npx prisma migrate deploy`.

## Google Calendar (необязательно)

Полностью опциональная интеграция — если не настроить, всё работает как
раньше, просто без календаря. Синхронизация в обе стороны:

- **Сайт → календарь**: как только вы подтверждаете заявку в Telegram
  (кнопка ✅), в календаре автоматически создаётся событие — все, у кого
  есть доступ к календарю (сотрудники студии), видят бронь, ничего
  вручную переносить не нужно.
- **Календарь → сайт**: если вы вручную ставите событие в Google Calendar
  (например, договорились по телефону) — это время автоматически
  становится недоступным для онлайн-записи на сайте.

Работает через служебный (service) Google-аккаунт — платной подписки
Google Workspace не нужно, обычного бесплатного календаря достаточно.

1. Откройте **console.cloud.google.com** → создайте новый проект (или
   выберите существующий) — кнопка выбора проекта вверху страницы →
   New Project. Это бесплатно, банковская карта не требуется.
2. В поиске сверху введите **Google Calendar API** → откройте →
   **Enable**.
3. Слева в меню: **APIs & Services → Credentials** → **Create
   Credentials → Service Account**. Придумайте любое имя (например
   `tmsound-booking-calendar`), остальные поля можно пропустить →
   **Done**.
4. Откройте созданный service account → вкладка **Keys** → **Add Key →
   Create new key → JSON** → скачается файл `.json`. Держите его в
   секрете — по нему можно управлять календарём.
5. Откройте скачанный файл текстовым редактором. Вам нужны два поля:
   - `client_email` — это адрес вида
     `tmsound-booking-calendar@ваш-проект.iam.gserviceaccount.com`
   - `private_key` — длинная строка, начинается с
     `-----BEGIN PRIVATE KEY-----`
6. В Google Calendar (в аккаунте студии, откуда вы обычно ставите
   брони) откройте настройки нужного календаря → **Share with specific
   people** → добавьте `client_email` из шага 5 → права **Make changes
   to events**.
7. Там же, в настройках календаря, найдите **Calendar ID** (в разделе
   «Integrate calendar») — обычно это просто email аккаунта студии, если
   это его основной календарь.
8. Впишите в переменные окружения (локально в `.env`, на хостинге —
   Settings → Variables):
   ```
   GOOGLE_CALENDAR_ID="calendar-id-из-шага-7"
   GOOGLE_SERVICE_ACCOUNT_EMAIL="client_email-из-шага-5"
   GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY="весь-private_key-из-шага-5-одной-строкой"
   ```
   Про `PRIVATE_KEY`: в JSON-файле он многострочный (с настоящими
   переносами), а в `.env` должен быть одной строкой — символы переноса
   там уже записаны как `\n` (два символа: обратный слэш и n), просто
   скопируйте значение поля `private_key` из JSON как есть, в кавычках —
   код сам разворачивает `\n` обратно при чтении (см.
   `src/lib/googleCalendar.ts`).
9. Передеплойте приложение — готово. Если календарь недоступен или
   переменные не заданы, сайт и бот продолжают работать как обычно,
   просто без синхронизации (ошибки логируются, но ничего не ломают).

## Деплой (Railway — по умолчанию)

1. Залейте этот проект в свой GitHub-репозиторий.
2. На railway.app → New Project → Deploy from GitHub repo → выберите
   репозиторий.
3. Add → Database → PostgreSQL (в тот же проект) — `DATABASE_URL`
   подставится в переменные окружения приложения автоматически.
4. В Settings → Variables приложения добавьте остальные переменные из
   `.env.example` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`,
   `TELEGRAM_ADMIN_CHAT_ID`, `TELEGRAM_WEBHOOK_SECRET`).
5. Settings → Networking → Generate Domain — получите
   `*.up.railway.app` адрес, впишите его в `PUBLIC_APP_URL`.
6. После первого деплоя выполните миграции и сид один раз (Railway →
   вкладка проекта → Shell, либо локально с тем же `DATABASE_URL`):
   ```bash
   npx prisma migrate deploy
   npm run db:seed
   ```
7. Локально (или там же в Shell) выполните `npm run bot:set-webhook`.

## Сайт и домен

С этого момента `/` — это главная страница сайта T&M Sound (перенесена
из макета в Claude Design canvas в обычный React/Next.js,
`src/app/page.tsx` + `src/app/site.css`), а `/booking` — отдельная
страница только с формой брони (её отдельная ссылка по-прежнему нужна,
например для кнопок в Telegram-боте). Раздел «Как записаться» на
главной теперь содержит саму форму бронирования (`<BookingWizard />`)
прямо на странице — без iframe, это тот же React-компонент, что и на
`/booking`.

Раз сайт и бронирование теперь один и тот же Next.js-процесс, никакой
прокси/поддомен-эквилибристика больше не нужна — то, что раньше
называлось «вариант А» (прокси на путь) или «вариант Б» (поддомен),
отпадает само собой. Остаётся просто привязать домен к корню Railway-
сервиса:

1. Купите домен (например, `tmsound.ru`), если ещё нет.
2. В Railway: проект → сервис → Settings → Networking → Custom Domain
   → впишите домен, Railway покажет CNAME/A-запись.
3. Добавьте эту запись в DNS у вашего регистратора/хостинга домена.
4. Подождите обновления DNS (обычно от нескольких минут до пары
   часов) — после этого домен откроет главную страницу, а
   `<домен>/booking` — форму отдельно.

`NEXT_PUBLIC_BASE_PATH` в этой схеме не нужен — оставьте пустым.

## Проверка по вашему чек-листу готовности

1–9 (услуга → дата → часы → продолжительность → Telegram → заявка →
получение в Telegram) — обычный путь пользователя через
`/booking`.

10–13 (подтвердить → слот занят → клиент получил подтверждение → второй
человек не может забронировать это же время) — проверяются кнопками в
Telegram и повторной попыткой создать пересекающуюся бронь через форму.

Отдельно, что стоит проверить руками:

- **Двойное бронирование**: откройте `/booking` в двух вкладках, в обеих
  дойдите до одного и того же времени, отправьте почти одновременно —
  вторая заявка получит `409` и сообщение «время только что заняли»
  (это тот самый DB-уровневый `EXCLUDE`, проверенный вручную при
  разработке — см. `prisma/migrations/20240101000100_overlap_protection/`).
- **Пересекающиеся часы**: попробуйте выбрать продолжительность, которая
  залезает на уже занятый час, — соответствующая кнопка продолжительности
  будет задизейблена.
- **Отмена**: подтверждённую бронь можно отменить (пока — командой в коде
  `cancelBooking`; если нужна отдельная команда бота типа `/cancel <id>`,
  скажите — это пять минут добавить).
- **Блокировка**: `/block 28.08 15:00-18:00 Ремонт` в чате с ботом →
  время пропадает из свободных часов на сайте.
- **Прошлые даты**: в календаре недоступны, в API тоже (проверка и на
  фронте, и на бэке).
- **Мобильная версия**: `/booking` адаптивен, шаги — не одна форма
  целиком.
- **Невалидные данные формы**: обязательные поля (имя, Telegram) не дают
  уйти дальше без исправления.
- **Таймзона**: все часы — Europe/Moscow независимо от того, где сидит
  клиент и где физически стоит сервер (см. `src/lib/time.ts`).

шагом на своей машине запустите `npm run build` и, если TypeScript
